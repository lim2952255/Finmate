# 종목 상세 재무 학습 카드 설계

## 1. 문서 상태

- 상태: `KIS 데이터 수집·저장 및 시세/재무/투자자 탭 구현, 개념 학습 카드는 후속`
- 대상 화면: 종목 상세페이지
- 1차 대상 시장: 국내 주식
- 제품 목표: 주식 초보자가 재무지표의 숫자를 외우는 데 그치지 않고, 쉬운 비유와 실제 종목의 숫자를 통해 지표의 의미·계산 방식·서로의 관계와 한계를 이해하도록 돕는다.
- 현재 범위: 기업 재무 학습 카드와 강조 규칙
- 보류 범위: 공시, 증권 일정, 통합 캘린더, 뉴스, 재무 개념 설명 카드

이 문서는 제품·데이터·표현 계약의 기준 문서다. 현재 소스에는 5개 KIS API의 분기 데이터 수집,
API별 `updatedAt` 신선도 검사, DB 저장과 시세/재무/투자자 탭이 구현되어 있다. 개념 설명과 계산 관계
학습 카드는 아직 구현하지 않는다.

## 2. 냉정한 평가

### 2.1 결론

방향은 FinMate의 목적과 잘 맞으며 구현 가치가 높다. 단순 모의매매 기능은 다른 서비스와 차별화하기 어렵지만, 사용자가 주문 전에 기업의 재무 상태를 읽는 법을 배우게 하면 `학습 → 관찰 → 모의투자 → 결과 복기` 흐름을 만들 수 있다.

다만 다음과 같이 구현하면 교육 기능이 아니라 숫자 장식에 그친다.

- PER, PBR, ROE를 설명 없이 나열한다.
- 낮은 PER과 PBR은 초록색, 높은 수치는 빨간색으로 표시한다.
- 기준일과 결산 구분 없이 API의 최신 응답만 보여준다.
- 적자, 자본잠식, 음수 EPS·BPS에서도 동일한 산식과 문구를 사용한다.
- 서로 다른 업종이나 연결·별도 재무제표의 수치를 직접 비교한다.
- 제공기관의 계산값과 FinMate가 재계산한 값을 구분하지 않는다.

따라서 이 기능의 핵심은 `값을 많이 보여주는 것`이 아니라 다음 질문에 답하는 것이다.

```text
이 숫자는 무엇인가?
어떻게 계산하는가?
언제 유용한가?
언제 오해하기 쉬운가?
어느 시점의 데이터인가?
무엇과 비교해야 하는가?
```

FinMate가 만들려는 것은 일반 증권사의 요약 재무표가 아니라 `재무 개념 학습 카드`다. 사용자는 PER, PBR, ROE, EPS와 BPS를 각각 외우는 대신 다음 흐름으로 이해해야 한다.

```text
회사가 이익을 낸다
→ 주식 한 주에 돌아가는 이익인 EPS가 만들어진다
→ 현재 주가를 EPS와 비교하면 PER이 된다

회사가 가진 순자산을 한 주 기준으로 나눈다
→ BPS가 만들어진다
→ 현재 주가를 BPS와 비교하면 PBR이 된다

주주가 맡긴 자기자본으로 얼마의 이익을 냈는지 본다
→ ROE가 된다
→ EPS와 BPS의 관계를 이해하는 데도 연결된다
```

### 2.2 현재 코드와의 적합성

현재 `DomesticStockMetadata`에는 매출액, 영업이익, 당기순이익, ROE와 재무 기준일 등이 저장되어 있고, `StockMetadataDisplayInfo`가 이를 종목 상세의 일반적인 `기초 재무` 목록으로 표시한다.

이 데이터는 재사용할 수 있지만 현재 구조만으로는 교육 카드 요구사항을 충족하지 못한다.

- PER, PBR, EPS, BPS가 현재 국내 메타데이터 모델에 없다.
- 값과 쉬운 설명, 계산식, 해석 주의사항이 연결되어 있지 않다.
- 한 시점의 마스터파일 부가정보이므로 여러 결산기간의 추세를 표현할 수 없다.
- 데이터 출처, 연결/별도 여부, 연간/분기 여부와 산식 기준이 화면 계약에 없다.

기존 `기초 재무` 섹션을 즉시 제거하지 않는다. 새 학습 카드는 별도 화면 모델로 만들고, 중복 노출이 확인된 항목만 구현 단계에서 정리한다.

## 3. 제품 원칙

### 3.1 판단을 대신하지 않고 판단 방법을 가르친다

FinMate는 다음과 같은 매매 판단 문구를 만들지 않는다.

```text
저평가 종목입니다.
매수하기 좋은 가격입니다.
곧 상승할 가능성이 높습니다.
위험하므로 매도해야 합니다.
```

대신 관찰 가능한 사실과 해석의 한계를 함께 보여준다.

```text
PER이 같은 업종의 비교 기준보다 낮습니다.
다만 최근 이익이 감소했다면 낮은 PER만으로 저평가라고 판단할 수 없습니다.
```

업종 또는 과거 비교 데이터가 아직 없다면 비교 문장을 만들지 않는다.

### 3.2 숫자와 기준일을 분리하지 않는다

모든 카드에는 가능한 범위에서 다음 메타데이터를 함께 표시한다.

- 값
- 단위
- 재무 기준일 또는 기준 기간
- 수치 출처
- 연결/별도 재무제표 구분
- 연간/분기/최근 12개월 구분
- 조회 또는 수집 시각

기준을 확인할 수 없는 값은 그 사실을 표시한다. `0`, `-`, 빈 문자열을 같은 의미로 취급하지 않는다.

### 3.3 강조는 좋고 나쁨이 아니라 주목할 사실을 나타낸다

초기 버전에서는 절대 임계값만으로 재무지표를 긍정·부정 판정하지 않는다.

강조 가능한 항목:

- 값이 계산 불가능한 이유
- 기준일이 오래된 데이터
- 적자 때문에 PER을 계산할 수 없음
- 자본이 음수라 PBR 또는 ROE 해석이 부적절함
- 전년 또는 이전 기간 대비 큰 변화
- 같은 업종 및 동일 기준 데이터와 비교한 차이

강조 색상만으로 의미를 전달하지 않고 라벨과 설명을 함께 사용한다.

### 3.4 비유는 정의를 대체하지 않고 이해를 돕는다

초보자용 카드에는 쉬운 비유를 적극적으로 사용하되, 비유만 읽고 잘못된 결론을 내리지 않도록 실제 정의와 계산식을 반드시 함께 제공한다.

예를 들어 회사를 작은 가게에 비유할 수 있다.

```text
회사의 자기자본
= 가게를 시작하고 운영하기 위해 주인이 맡긴 돈

회사의 순이익
= 가게가 비용을 모두 내고 최종적으로 남긴 이익

ROE
= 주인이 맡긴 돈으로 가게가 얼마나 효율적으로 이익을 냈는지

EPS
= 가게의 전체 이익을 주식 한 장씩 나누어 본 금액

PER
= 주식 한 장의 가격이 그 한 장이 벌어들인 이익의 몇 배인지
```

비유 사용 원칙:

- 비유 다음에 정확한 금융 용어와 계산식을 표시한다.
- PER을 `원금 회수에 정확히 몇 년이 걸린다`고 설명하지 않는다. 현재 이익이 유지된다고 단순 가정한 감각적 비유일 뿐 실제 회수 기간이 아니다.
- BPS를 회사 청산 시 실제로 돌려받는 금액이라고 설명하지 않는다.
- ROE가 높으면 무조건 좋은 회사라고 설명하지 않는다. 부채와 작은 자기자본 때문에 높아질 수 있음을 함께 보여준다.
- 유아적인 표현보다 성인 초보자도 부담 없이 이해할 수 있는 생활 비유를 사용한다.
- 비유가 맞지 않는 업종이나 예외 상황에서는 억지로 적용하지 않는다.

### 3.5 실제 종목의 숫자로 계산 과정을 보여준다

일반적인 정의만 보여주지 않고 사용자가 현재 보고 있는 종목의 검증된 값으로 계산 과정을 보여준다.

```text
현재 주가 15,000원
EPS 1,000원

PER = 15,000원 ÷ 1,000원 = 15배

이 종목의 주가가 현재 주당순이익의 15배 수준이라는 뜻이에요.
```

계산에 사용한 가격과 재무 값의 기준이 맞지 않으면 계산 예시를 만들지 않는다. 제공기관의 PER만 있고 구성 값의 기준을 검증하지 못했다면 제공값을 표시하되 FinMate 계산식 결과인 것처럼 표현하지 않는다.

### 3.6 하나의 빵집 비유를 끝까지 연결한다

지표마다 서로 다른 비유를 새로 만들면 사용자가 용어는 기억해도 관계를 놓칠 수 있다. FinMate의 기본 학습 시나리오는 하나의 빵집을 공동 소유하는 상황으로 통일한다.

#### 기본 상황

```text
FinMate 빵집을 만들 때 주주들이 맡긴 돈       1,000만 원
빵집의 지분을 나눈 주식 수                         100주
빵집이 1년 동안 비용을 모두 내고 남긴 순이익      100만 원
시장에서 거래되는 빵집 주식 한 주의 가격           15만 원
```

이 예시는 지표 관계를 쉽게 이해하기 위한 단순화다. 실제 기업은 평균 자기자본, 우선주 귀속분, 가중평균 주식수, 연결재무제표와 다양한 회계 조정을 사용한다.

#### EPS: 빵집 이익을 한 주씩 나누면

```text
빵집 전체 순이익 100만 원 ÷ 주식 100주
= EPS 1만 원
```

설명:

> 빵집이 1년 동안 최종적으로 100만 원을 벌었고 빵집의 지분이 100주로 나뉘어 있다면, 주식 한 주가 벌어들인 이익은 1만 원으로 볼 수 있어요. 이것이 EPS예요.

EPS는 실제로 주주에게 1만 원을 현금 지급한다는 뜻이 아니다. 회사가 벌어들인 이익을 한 주 기준으로 바라본 수치다.

#### PER: 한 주가 번 이익과 주식 가격을 비교하면

```text
주식 한 주의 시장가격 15만 원 ÷ EPS 1만 원
= PER 15배
```

설명:

> 이 빵집 주식 한 주는 시장에서 15만 원에 거래되고, 그 한 주가 최근 이익 기준으로 1만 원을 벌었어요. 시장가격이 한 주의 이익보다 15배 높은 수준이라는 뜻이에요.

`현재 이익이 영원히 같다면 15년 만에 원금을 회수한다`고 단정하지 않는다. 미래 이익, 배당, 주가와 사업 환경이 계속 변하므로 PER은 실제 회수 기간이 아니다.

#### BPS: 빵집의 순자산을 한 주씩 나누면

```text
빵집 자기자본 1,000만 원 ÷ 주식 100주
= BPS 10만 원
```

설명:

> 빵집의 회계상 순자산을 주식 100주로 나누면 한 주당 10만 원이에요. 이것이 BPS예요.

BPS는 빵집을 오늘 정리했을 때 실제로 주주가 정확히 10만 원을 받는다는 뜻이 아니다. 자산의 실제 처분가격, 부채와 정리 비용이 다를 수 있다.

#### PBR: 한 주의 순자산과 주식 가격을 비교하면

```text
주식 한 주의 시장가격 15만 원 ÷ BPS 10만 원
= PBR 1.5배
```

설명:

> 시장에서는 회계상 한 주당 순자산이 10만 원인 빵집 주식을 15만 원에 거래하고 있어요. 주가가 BPS의 1.5배 수준이라는 뜻이에요.

시장이 빵집의 브랜드, 성장 가능성과 미래 이익을 평가한 결과일 수도 있으므로 PBR이 1배보다 높다는 이유만으로 비싸다고 단정하지 않는다.

#### ROE: 주주가 맡긴 돈으로 얼마나 벌었는지 보면

```text
빵집 순이익 100만 원 ÷ 자기자본 1,000만 원 × 100
= 단순화한 ROE 10%
```

설명:

> 주주들이 빵집에 맡긴 1,000만 원으로 1년 동안 100만 원의 이익을 냈어요. 맡긴 자본의 10%만큼 이익을 낸 셈이고, 이것이 ROE예요.

빵집이 대출을 많이 받아 자기자본을 작게 유지하면 ROE가 높아 보일 수 있으므로 부채와 함께 확인해야 한다.

#### 다섯 지표를 한 번에 연결하면

```text
전체 이익 100만 원
→ 한 주의 이익 EPS 1만 원
→ 주가 15만 원과 비교한 PER 15배

전체 자기자본 1,000만 원
→ 한 주의 순자산 BPS 10만 원
→ 주가 15만 원과 비교한 PBR 1.5배

전체 이익 100만 원 ÷ 자기자본 1,000만 원
→ 단순화한 ROE 10%
```

같은 단순화된 값에서는 다음 관계도 확인할 수 있다.

```text
EPS 1만 원 ÷ BPS 10만 원 = ROE 10%
PER 15배 × ROE 0.10 = PBR 1.5배
```

화면에서는 이 빵집 사례를 지표별로 잘라 반복하지 않고, 사용자가 `다음 개념`을 눌러 하나의 이야기로 이어서 학습할 수 있게 한다. 마지막 관계 카드에서 전체 흐름을 다시 합친다.

## 4. 1차 MVP 범위

### 4.1 필수 카드

| 지표 | 화면 역할 | 우선순위 |
|---|---|---|
| PER | 주가와 주당순이익의 관계 학습 | 필수 |
| PBR | 주가와 주당순자산의 관계 학습 | 필수 |
| ROE | 자기자본을 이용한 이익 창출 효율 학습 | 필수 |
| EPS | 한 주당 귀속되는 이익의 의미 학습 | 필수 |
| BPS | 한 주당 순자산의 의미 및 PBR의 기반 학습 | 필수 |

사용자가 말하는 `주당수익률`은 용어가 모호하므로 화면에서는 사용하지 않는다.

- `EPS`: 주당순이익
- `배당수익률`: 현재 주가 대비 주당 배당금 비율
- `주가수익률`: 특정 기간의 가격 등락률

세 개를 명시적으로 구분한다. 배당수익률은 신뢰할 수 있는 배당 데이터와 기준이 확보된 이후 추가한다.

### 4.2 2차 후보

- 부채비율
- 영업이익률
- ROA
- 매출액 증가율
- 영업이익 증가율
- 순이익 증가율
- 배당수익률
- 영업현금흐름과 잉여현금흐름

1차에서 많은 지표를 동시에 추가하지 않는다. 사용자가 PER, PBR, ROE, EPS와 BPS의 관계를 이해할 수 있는지를 먼저 검증한다.

### 4.3 MVP 카드 유형

MVP는 같은 모양의 수치 카드 다섯 개로 끝내지 않는다. 다음 카드 유형을 조합한다.

| 카드 유형 | 답하려는 질문 | 예시 |
|---|---|---|
| 지표 카드 | 이 숫자는 무엇인가? | PER 12.3배 |
| 개념 카드 | 쉬운 말로 무슨 뜻인가? | 주가가 한 주의 이익보다 몇 배인지 |
| 계산 카드 | 어떻게 계산했는가? | 주가 ÷ EPS |
| 관계 카드 | 다른 지표와 어떻게 연결되는가? | EPS → PER, BPS → PBR, BPS·EPS → ROE |
| 적용 카드 | 현재 종목에서는 어떻게 계산되는가? | 실제 주가와 EPS를 대입한 과정 |
| 주의 카드 | 언제 오해하면 안 되는가? | 적자 기업은 일반적인 PER 계산 불가 |

첫 화면에서는 핵심 값과 한 줄 비유를 보여주고, 사용자가 펼치면 정의·계산·관계·주의사항이 단계적으로 나타나는 구성을 우선한다.

## 5. 카드 표시 계약

각 카드는 다음 구조를 공통으로 사용한다.

```text
[지표명] [한글명]
[현재 값] [기준일]

한 줄 설명
계산식
어떻게 읽나요?
주의할 점
비교 정보(있을 때만)
데이터 출처 및 기준
```

관계 카드는 다음 구조를 사용한다.

```text
[어디서 시작하나요?]
회사가 벌어들인 순이익

[한 주 기준으로 바꾸면]
EPS

[현재 주가와 비교하면]
PER

[함께 확인할 것]
이익이 일시적인지, 최근 증가·감소하는지
```

PER 예시:

```text
PER · 주가수익비율
12.3배 · 2026년 2분기 기준

현재 주가가 주당순이익의 몇 배인지 보여줘요.

계산식
주가 ÷ EPS(주당순이익)

어떻게 읽나요?
투자자가 현재 이익의 몇 배를 주가로 지불하고 있는지 살펴보는 지표예요.

주의할 점
이익이 일시적으로 크거나 작으면 PER도 크게 달라질 수 있어요.
적자 기업은 일반적인 PER을 계산할 수 없어요.
```

## 6. 지표별 교육 계약

### 6.1 PER

- 이름: 주가수익비율
- 기본 식: `현재 주가 ÷ EPS`
- 단위: 배
- 설명: 현재 주가가 주당순이익의 몇 배 수준인지 나타낸다.
- 계산 불가: EPS가 0 이하이거나 신뢰할 수 없는 경우 일반적인 PER을 표시하지 않는다.
- 주의: 낮은 PER이 항상 저평가를 의미하지 않는다. 이익 감소 전망, 경기 민감도와 일회성 이익을 함께 봐야 한다.

### 6.2 PBR

- 이름: 주가순자산비율
- 기본 식: `현재 주가 ÷ BPS`
- 단위: 배
- 설명: 현재 주가가 한 주당 순자산의 몇 배 수준인지 나타낸다.
- 계산 불가: BPS가 0 이하이거나 자본이 음수인 경우 일반적인 PBR 해석을 제공하지 않는다.
- 주의: 금융업, 제조업과 무형자산 중심 기업은 자산 구조가 다르므로 업종 간 직접 비교를 피한다.

### 6.3 ROE

- 이름: 자기자본이익률
- 일반 식: `당기순이익 ÷ 평균 자기자본 × 100`
- 단위: 퍼센트
- 설명: 주주가 맡긴 자본으로 얼마나 이익을 냈는지 나타낸다.
- 주의: 부채 증가, 작은 자기자본 또는 음수 자기자본 때문에 값이 높거나 왜곡될 수 있다.
- 데이터 계약: 제공기관이 기말 자기자본 등 다른 기준으로 계산했다면 FinMate의 일반식과 제공값의 산식이 같다고 단정하지 않는다.

### 6.4 EPS

- 이름: 주당순이익
- 일반 식: `보통주 귀속 순이익 ÷ 가중평균 유통주식수`
- 단위: 통화/주
- 설명: 회사가 주식 한 주당 얼마의 이익을 냈는지 나타낸다.
- 주의: 기본 EPS와 희석 EPS, 연결과 별도, 연간과 분기 값을 구분해야 한다. 유상증자·전환사채 등으로 주식 수가 달라지면 순이익이 같아도 EPS가 변할 수 있다.

### 6.5 BPS

- 이름: 주당순자산
- 일반 식: `보통주 귀속 자기자본 ÷ 유통주식수`
- 단위: 통화/주
- 설명: 회계상 순자산을 주식 한 주 기준으로 나눈 값이다.
- 주의: 청산 시 실제로 주주가 받는 금액을 보장하지 않으며, 무형자산과 자산 평가 방식의 영향을 받는다.

### 6.6 지표 관계 카드

#### EPS와 PER

```text
순이익
→ 주식 한 주 기준으로 나누면 EPS
→ 현재 주가를 EPS로 나누면 PER
```

회사가 같은 이익을 내더라도 주가가 오르면 PER은 높아지고, 주가가 내리면 PER은 낮아질 수 있다. 주가가 그대로여도 EPS가 증가하면 PER은 낮아질 수 있다. 따라서 PER의 변화가 가격 때문인지 이익 때문인지 함께 확인하도록 가르친다.

#### BPS와 PBR

```text
자기자본
→ 주식 한 주 기준으로 나누면 BPS
→ 현재 주가를 BPS로 나누면 PBR
```

PBR이 낮아진 이유도 가격 하락과 BPS 변화로 나누어 살펴보게 한다. 자산의 질과 업종 특성을 보지 않고 낮은 PBR만으로 저평가라고 결론 내리지 않는다.

#### EPS, BPS와 ROE

단순화한 동일 기준에서는 다음 관계로 직관을 설명할 수 있다.

```text
ROE ≈ EPS ÷ BPS × 100
```

예시:

```text
EPS 1,000원
BPS 10,000원

단순화한 ROE ≈ 1,000원 ÷ 10,000원 × 100 = 10%
```

다만 실제 ROE는 일반적으로 평균 자기자본을 사용하고 EPS·BPS도 가중평균 주식수, 기말 주식수, 연결/별도와 귀속 기준이 다를 수 있다. 따라서 이 식은 관계를 이해하기 위한 교육용 근사이며, 제공기관의 ROE를 검증 없이 재계산하는 공식으로 사용하지 않는다.

#### PER, PBR과 ROE

같은 시점·같은 회계 기준의 값을 단순화하면 다음 관계를 학습에 활용할 수 있다.

```text
PBR ≈ PER × ROE
```

이때 ROE는 퍼센트 숫자가 아니라 소수로 사용한다.

```text
PER 15배
ROE 10% = 0.10

PBR ≈ 15 × 0.10 = 1.5배
```

이 관계는 `PER이 낮다`, `PBR이 낮다`, `ROE가 높다`를 서로 독립적인 정답처럼 보지 않게 해준다. 실제 제공값은 산식과 기준 기간 차이로 정확히 일치하지 않을 수 있으므로 화면에는 `관계 이해를 위한 단순화`라고 명시한다.

## 7. 강조 및 비교 정책

### 7.1 MVP

업종 비교 데이터와 시계열 기준이 충분하지 않은 MVP에서는 다음만 강조한다.

- 값 제공 여부
- 계산 불가 사유
- 데이터 기준일
- 오래된 데이터 경고
- 전년 동기 또는 이전 동일 기준 기간 대비 변화가 검증된 경우의 방향

`PER 10배 이하 = 좋음` 같은 전역 임계값은 사용하지 않는다.

### 7.2 비교 기능 추가 후

비교 우선순위는 다음과 같다.

1. 같은 기업의 과거 3~5년
2. 같은 업종의 중앙값
3. 동일 시장·유사 규모 기업

비교 데이터는 같은 재무 기준을 사용해야 한다.

- 같은 연결/별도 기준
- 같은 연간/분기/TTM 기준
- 가능한 한 같은 기준일
- 같은 통화와 단위

평균은 극단값에 크게 영향을 받으므로 업종 비교에는 중앙값을 우선 검토한다.

MVP에서 `주식현재가 시세`와 `재무비율`을 함께 쓰는 이유는 역할이 다르기 때문이다. 현재가 응답은 지금 화면에 보여 줄 PER·PBR·EPS·BPS를 제공하지만 회계 기준 기간을 충분히 설명하지 않는다. 재무비율 응답은 `stac_yymm`과 연간·분기 구분을 제공하므로 과거 비교와 ROE 관계 설명에 적합하다.

손익계산서와 대차대조표는 개념카드 1차 버전이 안정된 후 추가한다. 두 API를 붙이면 `순이익 ÷ 주식 수 → EPS`, `자기자본 ÷ 주식 수 → BPS`라는 빵집 비유를 실제 기업 수치로 확장할 수 있지만, 연결/별도 기준과 주식 수 기준이 확인되기 전에는 KIS 제공 EPS·BPS와 동일하다고 단정하거나 직접 재계산하지 않는다.

다음 API는 현재 범위에서 제외한다.

- `배당률 상위`는 개별 종목의 재무 상세가 아니라 시장 순위 조회이므로 사용하지 않는다.
- 투자자 동향, 순위, 공시·일정 API는 종목 재무 개념카드와 직접 관계가 없으므로 보류한다.
- 재무비율 API와 값이 겹치는 수익성·안정성·성장성 API를 첫 화면 요청에서 모두 호출하지 않는다.
- 공식 샘플 목록의 별도 `finance_ratio` 항목은 역할, 경로와 TR ID를 확인하기 전까지 사용하지 않는다.

### 8.3 API 검증 조건

공식 샘플의 함수명과 필드명만으로 화면 계약을 확정하지 않는다. 구현 착수 전에 실전투자와 모의투자 환경에서 대표 종목을 호출하여 다음을 기록한다.

- 보통주, 우선주, ETF·ETN, SPAC, 금융업 종목의 지원 여부와 누락값
- `FID_DIV_CLS_CODE`의 연간 `0`, 분기 `1`별 실제 기간과 데이터 범위
- 단위, 소수점, 음수, 빈 문자열, `-`, 0의 의미
- PER·PBR·EPS·BPS의 연결/별도, 최근 연간/TTM, 지배주주 귀속 기준
- 현재가 API 값과 재무비율 API 값이 다른 경우의 기준일과 우선순위
- 페이지 연속 조회값과 호출 제한, 오류·빈 응답 형식
- 해당 재무 API가 모의투자 서버에서도 실제 지원되는지 여부

KIS 손익계산서 공식 샘플의 필드 설명상 분기 조회값은 해당 연도의 누적 합계다. FinMate는 같은 연도의
직전 분기 누적값을 차감해 개별 분기 실적으로 환산한다. 1분기는 해당 연도의 첫 누적값을 그대로 사용한다.
직전 누적 분기가 없으면 개별 분기값으로 안전하게 환산할 수 없으므로 해당 분기의 파생 분석을 만들지 않는다.

KIS 공식 샘플 저장소는 예제 코드가 예고 없이 변경될 수 있다고 안내한다. 엔드포인트와 TR ID도 구현 시점의 API 포털 명세 및 실제 응답으로 재확인한다.

공식 README는 실전투자와 모의투자용 앱 키가 별도라고 설명하지만 각 재무 API의 모의투자 지원 여부까지 보장하지 않는다. 따라서 모의투자 서버 지원은 현재 미검증 상태로 관리한다.

### 8.4 데이터 우선순위

초기 국내 종목 데이터 우선순위 후보:

```text
검증된 KIS 재무/현재가 응답
→ 최신 저장 snapshot
→ 기존 DomesticStockMetadata의 마스터파일 값
→ 값 없음과 사유 표시
```

서로 다른 출처의 값을 조용히 섞어 하나의 산식으로 재계산하지 않는다. 예를 들어 현재 주가는 최신이지만 EPS의 기준이 불명확하면 자체 PER을 만들지 않고 제공기관의 검증된 PER 또는 `계산 기준 확인 필요` 상태를 사용한다.

### 8.5 저장 모델 방향

`Stock`에는 PER, PBR, ROE 같은 변동 데이터를 직접 추가하지 않는다.

여러 기간과 출처를 지원하게 되면 별도 snapshot이 필요하다.

```text
StockFundamentalSnapshot
- stockId
- source
- fiscalPeriodEnd
- fiscalPeriodType
- statementScope
- per
- pbr
- roe
- eps
- bps
- debtRatio
- operatingMargin
- currency
- fetchedAt
- sourceVersion 또는 원본 기준 식별자
```

정확한 엔티티와 제약조건은 KIS 실제 응답을 확인한 뒤 결정한다. 한 종목에 snapshot 하나만 저장하는 구조는 과거 비교와 정정 데이터 반영을 막으므로 피한다.

### 8.6 숫자 처리

- 외부 원본 문자열은 경계에서 검증하고 도메인·화면 모델에서는 `BigDecimal`을 사용한다.
- API의 빈 문자열, `-`, `0`, 음수와 null을 구분한다.
- 통화, 배수, 퍼센트와 주당 금액 단위를 명시한다.
- 표시 반올림과 계산 반올림을 분리한다.
- 제공값과 FinMate 계산값을 구분할 수 있어야 한다.

## 9. 조회와 장애 정책

- 종목 상세 요청마다 모든 재무 API를 연속 호출하지 않는다.
- 재무제표 기반 값은 기준 기간이 바뀔 때 갱신하고, 현재가에 따라 변하는 값은 별도 신선도 정책을 둔다.
- 캐시 또는 DB에 유효한 이전 snapshot이 있으면 외부 API 장애 시 함께 기준일을 표시하고 반환할 수 있다.
- 일부 지표만 실패하면 전체 종목 상세페이지를 실패시키지 않는다.
- 값이 없을 때 0으로 대체하지 않는다.
- 데이터가 오래됐으면 숨기기보다 `기준일이 오래된 정보예요`라고 표시한다.

정확한 TTL과 갱신 주기는 KIS 호출 제한, 응답 특성과 실제 화면 트래픽을 측정한 뒤 정한다.

### 9.1 최신값과 기간별 값의 분리

모든 지표를 일자별로 저장하지는 않지만, 서로 다른 수명주기의 값을 하나의 최신 행에 덮어쓰지도 않는다.

- 현재가와 현재가 기반 PER·PBR은 자주 변하므로 Redis의 짧은 TTL 캐시 또는 별도 현재값 영역으로 관리한다.
- EPS·BPS·ROE와 재무제표 값은 결산 발표 때 바뀌므로 `종목 + 연간/분기 + 결산기간 + 출처`별 snapshot으로 저장한다.
- 같은 결산기간의 정정 데이터는 해당 snapshot을 갱신하고 `fetchedAt`을 기록한다.
- 기간별 snapshot은 일별 이력을 쌓는 구조가 아니다. 한 기업의 과거 3~5년 비교와 값의 기준 설명에 필요한 최소 이력이다.

재무정보가 오래됐는지는 단순히 `오늘 - fetchedAt`만으로 판단하지 않는다. `fiscalPeriodEnd`, 최신 결산 발표 가능 시점, 마지막 조회 시각과 재조회 간격을 함께 사용한다. 같은 날 상세페이지를 반복 조회해도 재무 API를 계속 호출하지 않도록 실패 재시도 간격도 둔다.

### 9.2 동시 갱신과 캐시 스탬피드 방지

여러 사용자가 오래된 동일 종목을 동시에 조회할 때는 종목·데이터 종류별 single-flight 갱신을 적용한다. FinMate는 이미 Redis를 사용하므로 다중 애플리케이션 인스턴스까지 고려한 Redis 기반 짧은 임대 락을 우선한다.

```text
요청 A, B가 동일 종목 조회
        ↓
DB snapshot이 신선함 ── 예 ──> 즉시 반환
        │ 아니오
        ↓
Redis SET NX로 refresh lock 획득 시도
        ├─ A 획득 성공
        │    ├─ DB를 다시 조회하는 double-check
        │    ├─ 여전히 오래됐으면 KIS 한 번 호출
        │    ├─ 짧은 DB 트랜잭션으로 upsert
        │    └─ 자신이 발급한 토큰을 확인하고 락 해제
        │
        └─ B 획득 실패
             ├─ 기존 snapshot이 있으면 기준일과 함께 즉시 반환
             └─ 최초 데이터도 없으면 짧게 기다린 뒤 DB 재조회,
                그래도 없으면 일시적 조회 불가 응답
```

권장 키 예시는 `lock:stock-fundamental:{stockCode}:{dataType}`이다. 서로 독립적인 현재가와 재무비율 갱신이 불필요하게 서로를 막지 않도록 `dataType`을 포함한다.

락 구현은 다음 조건을 지킨다.

- 락에는 KIS 최대 응답 시간보다 여유 있는 짧은 만료시간을 반드시 둬서 서버 장애 시 영구 락을 막는다.
- 각 락 값에 임의의 소유 토큰을 넣고, 해제할 때 토큰이 같은 경우에만 원자적으로 삭제한다.
- 락을 얻은 뒤 DB를 다시 확인하여 앞선 요청이 이미 갱신했다면 KIS를 호출하지 않는다.
- KIS 호출 중에는 DB 비관적 락이나 긴 DB 트랜잭션을 유지하지 않는다.
- 락 만료 뒤 늦게 도착한 응답이 더 최신 데이터를 덮어쓰지 않도록 결산기간·원본 기준일 또는 버전 조건으로 upsert한다.
- Redis 장애 시 중복 외부 호출을 허용하는 것보다, 기존 snapshot을 반환하고 갱신을 다음 요청으로 미루는 보수적 fallback을 우선한다.

기존 snapshot을 즉시 돌려주고 한 요청만 뒤에서 갱신하는 `stale-while-revalidate` 방식이 종목 상세페이지에는 가장 적합하다. 사용자가 재무정보 갱신 때문에 화면을 기다리지 않으며, 화면에는 반드시 데이터 기준일을 표시한다. 최초 조회처럼 저장값이 전혀 없는 경우에만 락 보유 요청의 완료를 짧게 기다린다.

## 10. AI 사용 원칙

1차 구현에는 AI가 필요하지 않다.

- 지표 정의와 주의사항은 검토된 정적 콘텐츠로 관리한다.
- 계산과 비교는 결정적인 규칙으로 수행한다.
- 강조 이유는 규칙의 결과로 만든다.

AI는 이후 검증된 수치와 판정만 입력받아 초보자용 문장을 다듬는 보조 역할로 제한할 수 있다. AI가 재무 원본을 직접 계산하거나 누락된 값을 추정하게 하지 않는다.

비유와 개념 설명도 1차 버전에서는 AI가 매번 생성하지 않는다. 검토된 정적 콘텐츠를 사용해 같은 개념을 일관되게 설명하고, 잘못된 비유나 투자 권유 문구가 섞이지 않게 한다.

## 11. 화면 구성 제안

```text
종목 상세
├─ 현재가와 차트
├─ 기업 개요
├─ 재무 개념 학습
│  ├─ 이 회사의 이익은 한 주에 얼마인가? · EPS
│  ├─ 그 이익과 현재 주가는 어떤 관계인가? · PER
│  ├─ 한 주의 순자산은 얼마인가? · BPS
│  ├─ 그 순자산과 현재 주가는 어떤 관계인가? · PBR
│  └─ 맡긴 자본으로 얼마나 이익을 냈는가? · ROE
├─ 재무지표 한눈에 보기
│  ├─ PER
│  ├─ PBR
│  ├─ ROE
│  ├─ EPS
│  └─ BPS
├─ 지표 관계 한눈에 보기
├─ 실제 종목 숫자로 계산해 보기
├─ 지표별 자세히 알아보기와 주의사항
├─ 재무 추세(후속)
└─ 기존 종목 메타데이터 및 채팅
```

카드의 첫 화면에는 값과 한 줄 설명만 보여주고, `자세히 보기`에서 계산식과 주의사항을 펼치는 방식을 우선 검토한다. 모든 설명을 한 번에 펼치면 종목 상세페이지가 지나치게 길어질 수 있다.

## 13. 검증 기준

### 데이터 및 계산

- 동일 입력은 항상 동일한 표시와 강조 결과를 만든다.
- PER, PBR 계산 불가 조건을 테스트한다.
- 음수 EPS, 음수 BPS, 음수 자기자본과 null을 구분한다.
- 퍼센트와 배수 단위를 혼동하지 않는다.
- 기준일과 출처가 값과 함께 노출된다.
- 제공값과 자체 계산값의 일치 여부를 검증할 수 있다.

### 교육 문구

- 낮은 PER/PBR을 자동으로 좋은 종목이라 표현하지 않는다.
- 높은 ROE를 부채 확인 없이 긍정 판정하지 않는다.
- EPS를 주가수익률이나 배당수익률과 혼동하지 않는다.
- 비유만 표시하지 않고 정확한 용어와 계산식을 함께 제공한다.
- PER을 실제 투자금 회수 기간으로 단정하지 않는다.
- BPS를 청산 시 실제 수령액으로 단정하지 않는다.
- `ROE ≈ EPS ÷ BPS`, `PBR ≈ PER × ROE`는 동일 기준을 단순화한 교육용 관계임을 표시한다.
- 실제 종목 계산 예시는 기준이 검증된 값만 사용한다.
- 매수·매도 추천 문구를 만들지 않는다.

### 화면 및 장애

- 모바일에서도 카드 값, 기준일과 설명을 읽을 수 있다.
- 일부 지표가 없어도 나머지 카드와 종목 상세가 표시된다.
- 외부 API 장애가 기존 차트·주문·채팅 화면을 막지 않는다.
- 색상 없이도 상태와 주의사항을 이해할 수 있다.

## 14. 구현 전 남은 결정

- 국내주식 KIS API의 정확한 응답 필드와 산식
- PER/PBR을 제공값으로만 표시할지, 검증 가능한 경우 자체 계산도 병기할지
- 연결/별도 및 연간/분기 중 화면의 기본 기준
- 재무 snapshot의 갱신 주기와 보존 기간
- 업종 비교 데이터의 출처와 업종 분류 기준
- ETF, ETN, 우선주, SPAC처럼 일반 기업 지표가 부적절한 상품의 표시 정책
- 해외 종목의 재무 데이터 공급자와 국내 카드 간 비교 가능 범위

이 결정이 끝나기 전에는 수치 임계값을 이용한 좋음/나쁨 판정을 구현하지 않는다.
